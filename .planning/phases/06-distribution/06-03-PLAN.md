<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer/CI host → GitHub Releases | GH_TOKEN authorizes uploading release artifacts |
| GitHub Releases (public) → end-user machine | Anyone can download the unsigned installers |
| GitHub API → packaged macOS app | Notify-only check reads the latest release tag |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-06 | Information disclosure | GH_TOKEN exposure in shell history / CI logs / commits | mitigate | Token is a developer-machine/CI env var, never committed; the publish task explicitly forbids printing/echoing it; in CI use `${{ secrets.GH_TOKEN }}` secret injection (RESEARCH §Security Domain). |
| T-06-07 | Elevation of privilege | Gatekeeper/SmartScreen bypass instructions could be abused for non-official binaries | mitigate | README scopes the right-click→Open / Run-anyway steps to the app downloaded from the official `Theosantos/CrateKeeper` Releases page ONLY (D-02 + RESEARCH §Security Domain). |
| T-06-08 | Tampering | Draft release would silently break the updater feed | mitigate | `releaseType: release` (electron-builder.yml) + the Task 2 check requires a PUBLISHED (non-draft) v1.0.0 — RESEARCH Pitfall 4. |
| T-06-SC | Tampering | npm installs in this plan | n/a | This plan adds NO npm packages (README + release publish only). |
</threat_model>

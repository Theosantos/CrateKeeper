<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Releases CDN → packaged app | Windows auto-update downloads a new `.exe` + `latest.yml` over the network |
| GitHub API → packaged app | macOS notify-only check fetches release metadata over HTTPS |
| npm registry → build host | `npm install electron-updater` pulls a new production dependency |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03 | Tampering | MITM on Windows auto-update download | mitigate | electron-updater verifies the SHA512 checksum from `latest.yml` (served from GitHub Releases over HTTPS) before applying the update — a tampered `.exe` fails checksum and is rejected. |
| T-06-04 | Denial of Service | GitHub API rate limit on macOS version check | mitigate | `AbortSignal.timeout(5000)` + silent catch (D-08); anonymous GitHub limit (60 req/hr) is far above one check per launch — rate-limited users simply see no notification, app continues. |
| T-06-05 | Tampering | Unsigned Windows `.exe` / SmartScreen bypass | accept | Accepted v1 risk per D-01; users only Run-anyway apps from the official Releases page (D-02). NSIS auto-update on unsigned builds is the documented v1 path (Assumption A1); signing in v2. |
| T-06-SC | Tampering | `npm install electron-updater` | mitigate | Gated behind the Task 1 `blocking-human` legitimacy checkpoint (RESEARCH `[ASSUMED]` — slopcheck unavailable). Verified on npmjs.com as the official electron-userland monorepo package before install. |
</threat_model>

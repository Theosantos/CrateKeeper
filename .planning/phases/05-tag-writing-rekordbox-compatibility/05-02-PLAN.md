<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → tagger:apply-writes | Renderer invoke triggers a batch of file writes in main |
| pending_tag_edits.file_path → file write | DB-stored paths (renderer-originated) are dereferenced for writing |
| main → renderer (write-event push) | Per-file results streamed back via webContents.send |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-PT | Tampering | apply-writes path handling | mitigate | Every DB `file_path` re-validated with `resolvesUnderRoot(filePath, root)` before write; a path outside root is skipped/rejected, never written (V4 access control, carried from T-4-01) |
| T-05-IV | Tampering | metadata values from DB | mitigate | Phase 4 already enforced MAX_TEXT_LEN/MAX_KEY_LEN/ALLOWED_RATINGS on write to pending_tag_edits; `assertAudioExt` re-checks extension before dispatch (V5 input validation) |
| T-05-FF | Tampering | ffmpeg path for MP4 remux | mitigate | `resolveFfmpegPath({ rawPath: ffmpegStatic, isPackaged })` resolves the bundled binary; never user/DB input |
| T-05-TMP | Tampering | concurrent temp-file collision | mitigate | `isRunning` single-active guard + sequential per-file loop → no two writes race on the same deterministic `.ck-tmp` name |
| T-05-DOS | Denial | unbounded batch | accept | Pending queue is user-local and bounded by their own library (a few thousand files); sequential loop is non-blocking via async; no remote attacker surface |

No high-severity unmitigated threats remain.
</threat_model>
